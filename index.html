Snapshots, backups,
and a change of node.

Keep guest maintenance close to the machine. Each operation starts a real Proxmox task, with its status, final result and diagnostic logs shown in the workspace.

Save a snapshot
Name a restore point and add a description. Rollback and snapshot deletion require typed confirmation.
Start a backup
Choose an available backup storage, browse this guest’s existing archives, and follow new backup tasks through to their result.
Move to another node
Choose an available destination in the cluster. Proxmox checks whether the guest can migrate.

Availability depends on your Proxmox permissions, guest configuration and storage. Existing installations may need a role update; Proxmiu never expands permissions automatically.

Fine-tune cores, memory and start-at-boot settings while a guest is stopped. Review the changes first; pending changes and stale configuration checks protect edits made in Proxmox.

See what happened in Proxmox task history: choose a node or guest, inspect results and reopen retained logs after an agent restart. Provisioning runs remain separate, and history follows Proxmox retention and permissions.

Everything you do every day.
Nothing you don't.

Proxmiu is a focused front end, not a replacement for the Proxmox UI. It makes the common things fast and leaves cluster administration where it belongs.

Power actions

Start, shut down or reboot selected guests with individual results. Keep one-click actions for each machine and typed confirmation for destructive operations.

SSH in the browser

A full xterm terminal to any guest or node, with copy/paste, select all and sticky Ctrl/Alt/Shift keys for phones.

Templates that do the work

Create a container or clone a cloud-init VM, then install your stack over SSH with a live log.

Community Scripts

Browse the community-scripts.org catalogue and turn any container app into a template, with options and resources prefilled.

Updates in the UI

Re-run a guest's template or the upstream Community Scripts update path from the guest menu. Opt in to updating the agent itself from Settings.

Built for the phone

Bottom navigation, touch-friendly actions and a terminal key bar. Check the homelab from the couch.

Chat with Lynx.
Keep the controls.

A sharper eye on your setup. Add your own OpenAI, Anthropic or OpenRouter API key in the app’s Settings, then ask Lynx for help with Proxmox and Proxmiu. Your key stays encrypted on your agent.

Chat messages go to your configured provider when you send them. Lynx does not attach inventory, notes or logs automatically. Proxmiu never applies infrastructure changes automatically.

You choose what leaves.

  1. Choose a guest.Preview its resource settings and available recent usage. The preview includes no names, IP addresses, notes or secrets.
  2. Share on your terms.Approve the exact preview before your chosen provider receives it with your message.
  3. Review every change.Lynx can propose CPU, memory and boot settings. Check the before and after, then confirm. Proxmox permissions and configuration checks still apply.

Resource changes require a stopped guest and supported configuration; Lynx never stops it for you. Settings also offers an anonymous inventory review. Without an AI key, the lynx stays a friendly companion.

One small agent. Your network stays yours.

Proxmox sends no CORS headers, and cloud hosts cannot reach a private LAN. So the UI talks to a small agent that runs at home — in an LXC, on a Debian box, or in Docker.

Make yourself at home.

Run this in the Proxmox shell. It creates an unprivileged container, installs the agent and adds the host to it.

Proxmox VE shell
bash -c "$(curl -fsSL https://raw.githubusercontent.com/LasseSLambertsen/proxmiu/main/scripts/proxmox-install.sh)"

On any always-on Debian or Ubuntu machine with systemd:

Debian / Ubuntu
curl -fsSL https://raw.githubusercontent.com/LasseSLambertsen/proxmiu/main/scripts/install.sh | bash

Then open http://<agent-address>:8787. The agent serves the UI itself. Add your Proxmox host under Connections if you installed the agent somewhere else.

Read the docs on GitHub

The UI never touches Proxmox directly.

Credentials are encrypted at rest, sessions are signed bearer tokens, and the agent refuses to listen beyond localhost without a password. Self-update is opt-in and limited to a narrow root helper.
